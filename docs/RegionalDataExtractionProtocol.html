Regional Data Extraction & Disaggregation Protocol

Architecture for high-fidelity school auditing and disaggregated reporting across Units 1–9.

1. Strategic Objective

The objective of the Regional Data Extraction utility is to provide a complete, disaggregated dataset for each region of the Department of Education (DepEd). This protocol ensures that school identities, enrollment data, and physical asset inventories are extracted from the InsightEd production tables into a standard tabular format (CSV) suitable for offline analysis by regional engineers and administrators.

2. Architectural Design

The "Relational Flattening" Strategy

Because Unit 7 data (Physical Facilities) exists in a many-to-one relationship with schools, a standard join would either omit data or collapse it. We implemented a **Flattening Pattern** where school metadata (Units 1-6, 8-9) is repeated for every building, repair, or demolition recorded. This ensures zero data loss during extraction.

Dynamic Column Pruning: The script performs a global introspective discovery phase to exclude any columns that are entirely blank across all schools, significantly reducing file size and improving human readability.

4. Implementation Workflow

1

Environment Initialization

Load credentials from the encrypted .env file and establish a secure tunnel to the Azure PostgreSQL instance.

2

Empty Column Filtering

Iterate through information schema metadata to identify non-empty data columns globally.

3

Regional Disaggregation

Perform a multi-stage fetch grouped by region. Generate CSV artifacts using UTF-8 encoding in the exports/ directory.

5. Execution Guide

To execute the extraction on the production host or a local machine:

# Ensure dependencies are available
pip install psycopg2-binary python-dotenv

# Execute the extraction script
python extract_region_data.py

The resulting files will be generated in the ./exports directory, named following the pattern Region_Name_Full_Unit_Extract.csv.
