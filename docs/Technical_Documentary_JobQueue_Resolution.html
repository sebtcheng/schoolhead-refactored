Subject: ESF7 XLSB Scan Registration Stalemate

REF: RCA-2026-0423-ESF7 | DEPT: Infrastructure & Core API
Incident Date: 2026-04-23
Severity: P0 (Blocking Feature)
System: pg-boss @ 12.15.0
Environment: Staging (Cluster Mode)

1. Incident Overview

Following the integration of autonomous ESF7 audit parsing, the background job worker failed to pick up queued XLSB files. While the front-end successfully queued jobs (Status: PENDING), the internal polling mechanism was essentially paralyzed, leaving users stuck at 0% progress indefinitely.

2. Forensic Root Cause Discovery

The resolution required unravelling a "Triple-Nested Failure" that masked the worker's presence from the system.

Layer I: The Transport Conflict

pg-boss attempted to initialize its own connection pool using the default PostgreSQL port (5432). In the InsightEd Staging ecosystem, however, the database is strictly accessed via PgBouncer (Port 6432). This mismatch prevented even the initial database handshake from completing.

Layer II: The Stale Advisory Lock Deadlock

Worker registration was logically nested inside a DDL migration block gated by pg_try_advisory_lock(6666666). A zombie process from a prior failed deployment held this lock. Consequently, all new PM2 instances skipped the block, resulting in the worker registration code (boss.work()) never being invoked.

Layer III: The Bootstrap Reference Errors

After decoupling registration from the lock, the process crashed due to ReferenceError exceptions. The script tried to register auxiliary workers referencing non-existent handler functions (e.g., handleEsf7ApproveJob) and call renamed migration methods (hardenSchoolsIernSchema vs _OLD), aborting the script before the critical ESF7 worker was reached.

3. Applied Remediation

Standardized Connection Adapter

Standardized pg-boss to utilize the application's existing validated pool:

// api/index.js
const boss = new PgBoss({
  db: {
    // Fixes Port/DB Alias mismatch by sharing the app pool
    executeSql: (text, values) => pool.query(text, values)
  },
  schedule: false // Corrected v12 key
});

Structural Decoupling

Restructured the startup sequence to ensure worker registration is independent of migration state and added lock-flushing commands:

// Forcibly clear locks from crashed sessions
await migClient.query('SELECT pg_advisory_unlock_all()');

// Moved outside the lock check gate
console.log("💼 [JobQueue] Registering Workers...");
await boss.work('esf7-local-scan', { localConcurrency: 2 }, async (job) => { ... });
